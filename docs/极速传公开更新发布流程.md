# 极速传公开更新发布流程

极速传采用“私有源码仓库 + 国内外公开更新仓库”的发布结构：

- 私有源码：`DMwarrior/TurboFile-Windows-Source`
- GitHub 公开更新：`DMwarrior/TurboFile-Windows`
- Gitee 国内公开更新：`fkwarrior/TurboFile-Windows`

公开仓库只保存产品介绍、安装包、SHA-256 校验文件和更新清单，不保存应用源码。

## 发布新版本

1. 必须先提升 `package.json` 中的版本号。同一版本号覆盖安装包不会触发已安装客户端更新。
2. 完成编译、测试和 Windows x64 安装包打包。
3. 确认 GitHub CLI 已登录具有发布权限的账号：

   ```powershell
   gh auth status
   ```

4. 发布 GitHub 完整安装包：

   ```powershell
   npm run turbofile:publish-update -- .build\win32-x64\TurboFileSetup-win32-x64-1.169.0.exe .build\release-notes-v1.169.0.md
   ```

发布命令会自动：

- 创建或更新 `v<版本号>` Release；
- 上传 Windows x64 安装包；
- 计算并上传安装包 SHA-256；
- 更新固定 `updater` Release 中的 `update.json`；
- 更新固定 `updater` Release 中的 `update-proxy.json`；
- 将版本 Release 标记为 Latest。

5. 为 Gitee 创建具有仓库与 Release 写入权限的私人令牌，只通过当前 PowerShell 会话设置，不要写入文件：

   ```powershell
   $env:GITEE_TOKEN = '<Gitee 私人令牌>'
   $env:GITEE_OWNER = 'fkwarrior'
   $env:GITEE_REPO = 'TurboFile-Windows'
   ```

6. 发布 Gitee 国内分片与清单：

   ```powershell
   npm run turbofile:publish-update:gitee -- .build\win32-x64\TurboFileSetup-win32-x64-1.169.0.exe .build\release-notes-v1.169.0.md
   ```

Gitee 发布命令会创建缺失的公开分发仓库并同步中英文产品介绍和展示图；安装包按 90 MiB 分片上传。所有分片必须在未登录状态下通过大小与 SHA-256 校验，脚本才会最后更新 `main/updater/update.json`。客户端按 Gitee → GitHub 顺序检查，Gitee 清单可用时不会请求 GitHub。

私有源码仓库中的 `TurboFile Update Manifest` 工作流需要配置名为 `TURBOFILE_RELEASE_TOKEN` 的仓库 Secret；该令牌只需要公开更新仓库的 Release 写入权限。不要把令牌写入源码或安装包。

## 发布后验证

以下地址必须无需登录即可访问：

```text
https://api.github.com/repos/DMwarrior/TurboFile-Windows/releases/latest
https://github.com/DMwarrior/TurboFile-Windows/releases/download/updater/update.json
https://github.com/DMwarrior/TurboFile-Windows/releases/download/updater/update-proxy.json
https://gitee.com/fkwarrior/TurboFile-Windows/raw/main/updater/update.json
```

验证两个清单中的版本号、安装包 URL 和 SHA-256 与本地构建产物完全一致，并在屏蔽 GitHub 的网络环境中完成一次 Gitee 分片下载、合并和启动安装后，再通知用户更新。
