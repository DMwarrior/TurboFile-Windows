# 极速传公开更新发布流程

完整源码和安装包统一发布至两个公开仓库：

- GitHub：`DMwarrior/TurboFile-Windows`
- Gitee：`fkwarrior/TurboFile-Windows`

自动更新优先国内 Gitee 分片，GitHub 提供标准 EXE 和备用源。只有国内分片匿名下载验证通过后，才能切换更新清单。

## 构建与验证

1. 更新 `package.json`、`package-lock.json`、README 的版本和下载链接。
2. 新增 `docs/releases/<版本>.md`，同步应用内 `turbofileReleaseNotes.ts`，保留历史记录。
3. 先运行 `npm run compile-check-ts-native`，通过后刷新 `out` 并执行相关回归、故障注入和必要的真实传输性能比较。不得用旧编译产物验证新代码。
4. 提交源码与版本说明，此时保留上一版本的 `updater/update.json`。
5. 依次运行：

   ```powershell
   npm run gulp -- vscode-win32-x64-min
   npm run gulp -- vscode-win32-x64-inno-updater
   npm run gulp -- vscode-win32-x64-user-setup
   ```

6. 将 `.build\win32-x64\user-setup\极速传Setup.exe` 复制为 `TurboFileSetup-win32-x64-<版本>.exe`，核对内嵌版本、构建提交、SHA-256 和启动结果。
7. 将源码提交及对应 `v<版本>` 标签同步到两个仓库。每个新版本使用新版本号，不附加“修订版”安装包名称。

## 先发布国内安装包

具备 Gitee 发布令牌时，通过当前进程环境变量 `GITEE_TOKEN` 提供凭据；不要写入源码或公开日志。设置 `TURBOFILE_UPDATE_MANIFEST_OUTPUT` 为暂存清单路径后执行：

```powershell
npm run turbofile:publish-update:gitee -- <标准安装包路径> docs/releases/<版本>.md
```

也可通过已登录的 Gitee 网页创建发行版并上传相同产物。安装包按 32 MiB 分片，另附 SHA-256 文件和国内安装脚本。网页上传后也必须以未登录请求下载每个分片，核对长度及 SHA-256，合并后再核对完整安装包。

任何分片缺失、下载需要登录、大小或校验不符，都不得更新客户端清单。

## GitHub 与更新清单

将已验证的国内清单路径设置到 `TURBOFILE_UPDATE_DOMESTIC_MANIFEST` 后执行：

```powershell
npm run turbofile:publish-update -- <标准安装包路径> docs/releases/<版本>.md
```

脚本上传标准 EXE 与校验文件，保留国内 `parts`，更新固定 `updater` 发行版中的 `update.json`、`update-proxy.json`，将新版本标记为 Latest。

最后把已验证清单写入 `updater/update.json`，中文提交并同步两端。不要用旧的 `turbofile:update-manifest` 工作流重新生成缺少国内分片的清单。

## 发布后验证

- 两个公开仓库的源代码和版本标签指向实际构建提交。
- GitHub 标准 EXE 可匿名下载，大小与 SHA-256 匹配本地安装包。
- Gitee 原始清单、GitHub 两份更新清单的版本、完整包校验及国内分片一致。
- 国内分片无需 GitHub 即可下载、合并并通过完整校验。
- 应用内更新说明可显示新版本主要变化；旧客户端会根据版本比较获取最新清单，其自身下载能力不由清单升级。
