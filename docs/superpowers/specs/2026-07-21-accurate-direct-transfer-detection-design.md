# SSH 设备直连准确判定设计

## 背景

当前 SSH 到 SSH 的传输虽然默认先尝试直连，但直连候选并非通过真实连通性检测得到，而是直接乐观返回 `source-push` 与 `target-pull`。直连数据流程中的任意异常都会被记录为路线失败，并触发长达十分钟的冷却。目标文件增长查询、路径准备、磁盘、协议命令、最终大小校验等非网络错误因此可能把实际可直连的设备误判为不可直连，后续传输直接进入中转。

已对 60 服务器与 NAS 完成只读实测：60 到 NAS 的 TCP、SSH 握手、账号认证，以及软件同款 `sshpass + ssh` 参数均成功；NAS 到 60 的反向认证也成功。这证明当前中转显示来自传输流程误判，而不是网络不通。

## 目标

- SSH 到 SSH 传输始终优先真实直连。
- 正常直连成功路径不增加预检测，不影响启动时间与传输速度。
- 只有网络不可达、端口失败、SSH 握手失败或认证失败才能判定某个方向不可直连。
- 路径、权限、磁盘、进度、协议、校验等错误不能污染直连能力状态。
- 数据阶段失败时自动重试一次直连；仍失败时允许中转以保证稳定性。
- 一次中转不能阻止下一次传输重新优先尝试直连。
- 状态栏与任务日志始终显示本次实际使用的数据路径。

## 非目标

- 不改变 SCP、tar、rsync、SFTP 的数据参数、并发度或缓冲区配置。
- 不增加常驻 SSH ControlMaster 进程。
- 不扫描传输内容总大小。
- 不改变本地到 SSH、SSH 到本地和同机传输策略。
- 不改变复制、剪切、回收站或传输完成后的刷新规则。

## 核心原则

### 实际传输即首轮判定

不在正常路径上增加独立 TCP 或 SSH 预检测。用户触发任务后立即执行真实直连传输。真实直连成功即证明当前方向可用，正常成功路径没有额外往返。

### 能力判定与数据结果分离

直连能力只描述执行服务器能否使用目标设备的账号完成 SSH 登录。数据传输结果描述路径、文件系统、协议命令和数据完整性。两者采用独立状态与错误类型，禁止根据普通数据错误写入直连失败状态。

### 失败后才验证

真实直连失败后，使用与实际协议相同的执行方向、主机、端口、用户名、认证方式和 SSH 兼容参数，执行只读认证命令。该命令不写入目标业务路径、不扫描目录、不计算大小。密码或 agent 认证不创建文件；私钥认证允许复用现有凭据准备逻辑，在执行设备 `/tmp` 创建权限为 `0600` 的随机临时身份文件，并必须在 `finally` 中无条件删除。

- 验证失败且错误属于网络、握手或认证：该方向在本次任务内不可用。
- 验证成功：该方向仍具备直连能力，原错误属于数据阶段。
- 验证本身发生无法归类的内部异常：不写入不可直连状态，按数据阶段失败处理。

## 传输流程

1. 按最近成功方向排序直连候选；没有历史时优先 `source-push`，其次 `target-pull`。
2. 立即执行第一个真实直连数据传输，不做预探测。
3. 成功后记录成功方向并结束任务。
4. 失败后对相同方向执行完整 SSH 认证验证。
5. 如果验证确认网络、握手或认证失败，尝试另一个直连方向。
6. 两个方向都被本次任务的认证验证确认不可用时，立即中转。
7. 如果验证成功，清理本次产生的未完成目标，再使用同一方向重试一次真实直连。
8. 重试成功则结束；重试仍失败则中转，但不改变设备对的直连能力。
9. 下一次新任务仍从真实直连开始，不继承本次任务的失败结论。

## 错误分类

### 直连能力错误

仅包括：

- DNS 或地址解析失败。
- TCP 连接超时、拒绝、重置或不可达。
- SSH 握手、算法协商或主机密钥协商失败。
- 用户名、密码或私钥认证失败。
- 远端 SSH 服务在配置端口不可用。

这类错误只在失败后的完整认证验证中确认，不能仅凭 SCP、tar、rsync 或 SFTP 的退出文本推断。

### 数据阶段错误

包括但不限于：

- 源路径不存在、目标路径不可写或权限不足。
- 磁盘空间不足、只读文件系统或配额限制。
- SCP、tar、rsync、SFTP 命令或依赖异常。
- 目标大小轮询、SFTP `stat` 或进度读取暂时失败。
- 数据停滞、命令退出、最终大小不一致或完整性校验失败。
- 无法可靠归类的内部异常。

数据阶段错误可以触发一次直连重试和最终中转，但不能写入直连不可用缓存。

## 超时与进度

- 目标文件增长查询仅用于显示已传输大小与速度，保持 best-effort，查询失败不能终止直连或改变能力判断。
- 移除当前以十秒“未观察到目标增长”直接判定路线失败的语义。
- 真实直连命令由 OpenSSH 的连接超时、ServerAlive 与退出状态负责发现网络断开。
- 如仍需数据停滞保护，停滞只能产生数据阶段错误，随后执行认证验证；不得直接进入路线冷却。
- 单文件继续显示“已传输/总大小”，多文件或目录继续只显示已传输大小，不引入大小预扫描。

## 状态与缓存

- 删除十分钟直连失败冷却和会阻止直连尝试的负缓存。
- 仅保留“最近成功方向”作为候选排序提示；它不能跳过另一个方向，也不能阻止新的真实直连尝试。
- 设备配置中的主机、端口、用户名或认证方式改变时清除成功方向提示。
- 能力验证结果只在当前任务中使用，不跨任务保存。

## 中转与界面语义

- 真实直连正在执行时显示对应的 `scp/tar/rsync/sftp 直连`。
- 数据阶段第一次失败并重试时显示“直连重试”。
- 网络或认证确认失败后中转，显示“直连不可用，正在中转”。
- 直连能力正常但两次数据传输失败后中转，显示“直连传输失败，正在中转”。
- 任务最终策略字段必须等于实际承载数据的路径；不能用预测策略覆盖实际结果。
- 任务日志保留首次直连错误、认证验证结果、重试结果和中转原因，但绝不记录密码、私钥或包含密码的完整命令。

## 复制与剪切安全

- 重试或中转前必须清理本次失败尝试产生的未完成目标，不能删除任务开始前已存在且未经确认可覆盖的内容。
- 剪切模式只有在最终直连或中转传输成功并完成现有完整性验证后才能删除源文件。
- 任何失败、取消、验证异常或中转失败都不得删除源文件，也不得把剪切源移动到回收站。
- 同一任务最多执行一次源文件删除。

## 协议覆盖

统一的失败分类与回退协调器覆盖：

- 单文件自动极速的 SCP 直连与 SCP 中转。
- 多文件或目录自动极速的 tar 直连与 tar 中转。
- 用户明确选择的 rsync 直连与 rsync 中转。
- 用户明确选择的 SFTP 直连与 SFTP 中转。

各协议保留现有高速数据实现，只替换路线判定、错误分类、重试和冷却逻辑。

## 测试标准

### 单元测试

- 正常直连成功时不调用额外认证验证，并保持直连结果。
- 网络或认证失败时验证失败，尝试另一方向；两向均失败后中转。
- 数据阶段失败且验证成功时只重试一次直连，随后按规则中转。
- 数据阶段失败不能写入负缓存，下一任务仍首先直连。
- 进度轮询失败不能终止传输或改变路线能力。
- 最近成功方向只改变候选顺序，不跳过其他方向。
- 日志与错误对象不包含密码或私钥。
- 复制与剪切均满足失败不删源、成功只删一次。

### 集成测试

- 60 到 NAS 与 NAS 到 60 完整认证直连。
- 60、61、62、57、NAS、64、5336 之间的 42 个有序设备对，分别通过实际服务执行单文件 SCP 与文件夹 tar，共 84 个用例，并核对最终 strategy、route 与数据完整性。
- 目标端口不可达时快速回退中转。
- 密码错误时准确归类认证失败。
- 目标目录无权限、磁盘不足和目标增长查询失败均不得标记设备不可直连。
- SCP、tar、rsync、SFTP 分别验证直连、重试和中转流程。
- 大文件、海量小文件和多个并发任务不共享错误状态。

### 性能回归

- 正常直连路径不新增探测命令，首个数据命令启动时间不得劣于当前版本。
- 不改变协议并发、块大小、压缩和数据缓冲参数。
- 只有已经失败的任务才承担一次认证验证与最多一次直连重试。

## 验收条件

- 可直连设备的正常任务始终直接启动直连。
- 非网络类错误不会让后续任务跳过直连。
- 中转发生时能够明确区分“直连不可用”与“直连数据失败”。
- 状态栏、任务日志和最终结果与实际数据路径一致。
- 所有现有 TurboFile 单元测试通过，新增路线判定测试通过，TypeScript 编译检查通过。
