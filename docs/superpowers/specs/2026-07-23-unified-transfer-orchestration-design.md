# TurboFile 统一传输编排设计

## 目标

在不改变现有高速数据通道参数、剪切安全语义和多文件免预扫描规则的前提下，统一传输错误、协议、进度、入口与调度行为，并生成 1.159.0。

## 设计

### 1. 统一错误、协议与进度状态

- 将传输失败归一为：取消、认证、权限、冲突、空间不足、协议不可用、直连不可用、网络瞬态、数据完整性、未知错误。
- 取消、认证、权限、冲突和空间不足属于终止错误，不切换协议，避免重复副作用。
- 协议不可用、直连不可用、网络瞬态和数据完整性错误可按计划进入下一安全尝试。
- 协议名称统一使用 `local/native/scp/sftp/tar/rsync`，展示名称由公共映射生成，不再从策略字符串零散推断。
- 进度状态统一为排队、准备、传输、回退、完成、失败、取消；进度事件同时携带实际协议与路由。
- SSH 单文件自动顺序为 SCP 直连、SFTP 直连、SCP 中转、SFTP 中转；本地与 SSH 单文件为 SCP、SFTP。

### 2. 统一传输规划器

- 单文件和批量请求都由 `resolveTransferPlan` 生成尝试序列。
- 面板拖拽、Windows 拖拽、Ctrl+C/V/X 最终都进入现有的 `transferFile` 或 `transferBatch` 服务入口，不在 UI 复制协议判断。
- 服务端根据规划器和统一错误分类决定继续、回退或终止；复制与剪切共用数据阶段，剪切仅在最终成功后清理源。
- 同机与同 SSH 仍使用原生复制/移动，不改为网络协议。

### 3. 自适应并发和路径级队列

- 队列访问由整设备独占改为“设备容量令牌＋规范化路径锁”。同一目标目录或祖先路径冲突的任务串行，独立目录可并行。
- 单个传输的数据流、缓冲区与协议内部并发保持原值，调度器只控制同时运行的任务数量。
- 普通 SSH 初始批量并发保持 16 文件/4 目录；共享存储形态初始为 8 文件/2 目录。
- 使用加性增大、失败减半的设备反馈调节并发；成功稳定后逐步恢复，瞬态/资源错误会降低并发，业务权限错误不污染容量判断。
- 本地并发维持现有上限。

## 不变量

- 失败或取消绝不删除源文件。
- 只有所有目标数据成功后，剪切才清理源文件。
- 单文件显示已传输/总大小；多文件和目录不递归预扫描总大小，只显示已传输量、速度和时间。
- 不降低单任务传输缓冲、分块或协议线程参数。
- 不对具体设备名称写死规则；共享存储只通过端点特征和运行反馈识别。

## 验证

- 公共层单测覆盖错误分类、协议顺序、进度映射、路径冲突、容量限制与自适应调节。
- 静态服务测试覆盖所有入口使用统一规划器、单文件 SFTP 兜底和剪切清理顺序。
- 运行 TypeScript 编译、TurboFile 单测、分层检查与打包烟雾验证。
