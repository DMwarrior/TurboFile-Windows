# Tar 失败后统一使用 SFTP 兜底

## 目标

所有会优先选择 tar 的传输路线，在 tar 不可用或执行失败时自动改用 SFTP 完成传输，同时不改变 tar 成功路径的性能与行为。

覆盖以下路线：

- 本机到 SSH、SSH 到本机。
- SSH 到 SSH 的直连与中转。
- 单个文件夹、多文件和多文件夹批量传输。

## 行为

- 单文件仍保持既有 SCP 等快速路径，不新增无关兜底。
- 本机与 SSH 之间的目录或批量传输按 `tar -> SFTP` 执行。
- SSH 与 SSH 之间保持既有 `tar 直连 -> tar 中转` 顺序，之后再尝试 `SFTP 直连 -> SFTP 中转`。
- 用户主动取消时立即结束，不能误判为 tar 失败并启动 SFTP。
- 剪切或移动操作只在最终传输完整成功后删除源文件；tar 失败和 SFTP 失败均不得删除源文件。
- SFTP 兜底继续复用现有进度、速度、耗时和已传输大小统计。

## 性能与稳定性

正常 tar 路径不增加预扫描、探测或额外连接，因此成功传输的速度不受影响。SFTP 只在 tar 已失败后创建连接。批量兜底通过克隆传输端点并强制其首选协议为 SFTP，避免子任务再次进入 tar 或 SCP 路径。

## 验证

- 传输计划测试覆盖全部 tar 路线及 direct/relay 策略过滤。
- 静态测试确认目录传输不再在 tar 失败后直接抛错，批量 SFTP 兜底强制使用 SFTP。
- 运行 TypeScript 编译检查、TurboFile 相关单元测试、分层检查及差异格式检查。
