## 修改与原因

| 项目 | 已确认问题与修复 |
| --- | --- |
| 设备顺序 | 设备卡片支持拖动，独立存储显示顺序，Windows 和 SSH 设备及设备下拉列表采用同一顺序；不改认证信息。 |
| 传输挂起/取消 | 为缺失回调、连接关闭、迟到通道、取消后迟到启动补终止处理；有持续数据进展的传输不受固定总时长限制。权限、空间、冲突、源消失/变化等错误保留原因并停止无意义的跨协议回退。 |
| 外观 | 删除独立外观页面及导航；五项字体设置移到“视图 → 字体”，已有配置继续生效。 |
| 同机速度 | 同机原生移动接入 progressId、事件订阅及取消；修复 awk 在大数下输出科学计数后被数字守卫清零，以及 stderr 分段/结束后迟到事件。实际字节增量进入已有速度计算与状态栏，未知总量也可显示速度。横向进度条保持原样隐藏。 |
| 同侧复制/剪切 | 限定可见活动编辑器的快捷键归属，重绘后焦点退回 body 时使用当前编辑器记录的侧；修正图片网格粘贴侧；冻结来源与目标；旧剪切完成不清除后来复制的内容；补文件/空白区域右键入口和输入法物理按键识别。 |

交叉审查发现并修复了本轮一处回归：把单项原生剪切改走 batch 会将既有 `renamePath` 的覆盖语义变成 `mv -n`。最终单项剪切仍走原有 rename，目录内批量移动仍走原有 `movePathsIntoDirectory`，只增加进度/取消观察。batch 默认拒绝覆盖的行为保持不变。

传输协议、并发数、分块/缓冲参数、原生 cp/reflink 参数保持基线。没有为百分比或结束统计加入新的目录扫描。500 ms 的界面时钟仅使用内存中的进度。

## 新增取消实测发现（保留失败证据）

在 60 上将独立的 512 MiB 文件从 `/home/th/Project_ssd` 跨文件系统移动到 `/tmp`，发现原先关闭 SSH 通道的取消实现不能保证远端 `mv` 已结束。取消接口约 4.9 ms 返回后，目标首次检查为 `403152896` 字节；等待 350 ms 后再次经 SSH 检查，已增长到 `536870912` 字节，源最终被 `mv` 删除。这是取消实现失败，不能计为取消成功；仅校验复制源哈希也无法发现同类后台写入问题。

实验仅涉及带 owner/realpath 校验的独立测试文件。失败后停止后续基准测试，确认该任务进程已结束并保存源/目标状态，再清理两个测试目录。

失败原始事件、结果及后续检查：`.build/turbofile-move-speed-c8451898-7699-40eb-9272-422fddae96fe/`。取消回归已加强为：取消结算后立即读取目标大小，等待后再次读取，检查停止增长、源哈希及批量任务后续项目未继续移动。

最终修复为原生 POSIX 复制/移动记录该 SSH 命令独占的进程组。取消时先核验进程组、会话及进程启动时间，再停止整组并确认退出，最后关闭连接；无法确认停止时报告失败，不伪报取消成功。单项、原生批量及 portable 批量入口均接入，正常传输没有增加 SSH 往返。没有按进程名或目录全局杀进程。

## 边界与用户复测

快速完成且总量未知的原生批量任务，可能在首个采样前结束，最终统计仍可为 0 B；任务完成不依赖该值。本轮没有用额外扫描换取结束统计，也不会为瞬时元数据移动虚构速度。

原生辅助进程的心跳只能证明进程存活，不能证明内核 I/O 一定前进；portable/Windows 静默跨卷移动没有新增数据超时，以避免终止合法的长移动。取消、通道打开及连接关闭仍有保护。真实环境无限组合不能由上述用例证明“没有任何 bug”。

所有实机测试使用带 owner/realpath 校验的独立临时目录；62 未访问，业务目录未改。用户复测建议：设备拖动后重启；同侧复制和剪切后换目录粘贴（含覆盖）；大目录复制时展开终端检查速度/字节/耗时；取消后立即再次传输；视图菜单调整五项字体。
