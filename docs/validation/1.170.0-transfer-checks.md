# 1.170.0 传输修复验证记录

日期：2026-09-11。**本记录不是全路线验收通过声明。**

## 已修复的 SSH 路线

- **SCP 目录直连：SSH A → SSH B，不经 Windows 搬运文件数据。**
  - 原实现传递 `目录/.`，旧 SCP 接收端拒绝 `.`；改为把具名目录复制到准确的目标路径，不预建多余一层目录。
  - 补充远端 shell 路径转义，覆盖中文、空格、引号、方括号、美元符号和分号；需要转义时按客户端能力选择旧协议参数，不关闭文件名校验。
  - 目录大小未知时，在复制结束后确认内容大小，不把最后一次采样值当作最终字节数。
- **密钥认证的 rsync 中转：SSH A → Windows 网络隧道 → SSH B。**
  - 移除目标必须提供密码的限制，探测与实际 rsync 使用相同的密钥感知 SSH 命令。
  - 仅密码认证依赖 sshpass；密钥处理复用既有临时凭据生命周期、权限限制、活动标记、退出清理及过期清理机制。
  - 单请求和批量接口均覆盖，保持原有网络转发、传输缓冲区和并发设置。

SCP 新旧协议和路径转义差异参见 [OpenSSH SCP 官方说明](https://man.openbsd.org/scp)。

## 本轮实机结果

测试端为 Windows 本机和 SSH 62/64。每例使用隔离临时目录，256 MiB 文件数据、中文嵌套路径、空文件，核对 SHA-256、最终字节、复制保留源/剪切移除源，以及实际返回的传输策略与中间进度。

| 场景 | 例数 | 结果 |
| --- | ---: | --- |
| SCP 双向批量复制/剪切、单请求复制及目标改名；密钥 rsync 中转双向批量复制/剪切和单请求复制 | 13 | 通过 |
| SCP 直连、rsync 中转，初始目录总大小未知 | 2 | 通过 |
| SCP 直连，中文和空格路径，两方向 | 2 | 通过 |
| SCP 直连，包含引号、方括号、美元符号及分号的路径，两方向及另一个执行端 | 4 | 通过 |

其中 19 例调用公共主进程服务接口，2 例直接调用实际 SCP 工作函数，以覆盖另外两个源推送/目标拉取执行组合。这不是鼠标、键盘或 Electron UI 测试。
